# 部署交接说明（给部署负责人）

> 你将收到的是「焦外述影」官网仓库的 `feat/admin` 分支：一个已开发完毕、
> 本地全链路测试通过的管理后台（账号密码登录 + 内容管理 + 发布回滚）。
> 本文档 3 分钟读完，照《部署配置手册》操作约 20 分钟完成上线。

## 一、这个分支包含什么

- **官网前台零改动**：所有区块渲染与线上完全一致（仅数据源从代码常量迁到 JSON）；
- **新增 `/admin` 管理后台**：管理组手机（微信内）使用，换群码/换作品/改文案，保存约 3 分钟自动全网上线，可一键回滚；
- **新增 `api/` 两个 Serverless 函数**：登录 + 内容读写（经 GitHub Contents API 以机器人身份提交，**成员无需 GitHub 账号**）；
- 两个 GitHub Action：PR 图片自动压缩、群码过期每日巡检提醒；
- 完整文档在 `docs/`：PRD、技术方案、模块架构、to-do（30/34 项已完成）、管理组使用说明。

## 二、你要做的事（按序）

1. **合并代码**：将 `feat/admin` 合并进 `main`（建议 PR 方式，CI 会自动跑图片压缩检查）；
2. **确认 Vercel 项目是 Git 集成模式**连接本仓库（Settings → Git），push 到 main 自动构建，`api/*.js` 自动部署为函数；
3. **配置 4 个环境变量 + 创建 1 个 PAT**：逐项步骤、值格式、验证方法见 **《[部署配置手册](部署配置手册.md)》§2~§3**（含 PAT 最小权限说明：仅本仓库、仅 Contents 读写）；
4. **上线验收**：手册 §4 有完整验收清单（手机微信登录 → 换码 → 3 分钟生效 → 回滚）。

## 三、硬性要求（安全相关）

- PAT 用 **Fine-grained** 类型，权限只给 Contents 读写，**不要**用有完整仓库权限的经典 token；
- `ADMIN_SECRET` 用随机 ≥32 字符串生成（手册有命令）；
- 账号密码只存 Vercel 环境变量 `ADMIN_ACCOUNTS`，**不要**写进任何文件/聊天记录/文档。

## 四、上线后的两件小事

- 在 GitHub 仓库点 **Watch → Watching**（否则群码过期巡检 Issue 不会邮件提醒你）；
- 给 PAT 设一年有效期并在日历记续期提醒（手册 §6）。

## 五、出问题找谁

- 代码/后台逻辑问题：仓库提交历史里找开发者（全部提交均有中文说明，`后台:` 前缀为管理组线上操作产生）；
- 改坏了内容：后台「发布历史」一键回滚，或 GitHub revert——**不需要找任何人**；
- 详细故障对照表：手册 §7（对应 PRD EB-1~EB-10）。
