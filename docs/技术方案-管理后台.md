## 1. 总体架构

```
管理组手机（微信内置浏览器）
   │  https://hhxyjwsyst.online/admin
   ▼
┌─────────────────────────────────────────────────┐
│ Vercel 项目（同一个仓库，一次部署）                │
│                                                 │
│  前台  React 19 + Vite 静态产物（现状不动）        │
│  后台  /admin 单页（public/admin/index.html）     │
│  接口  api/login.js      登录 + 会话              │
│        api/content.js    内容读写/上传/回滚        │
│        api/_lib.js       共享库（非路由）          │
└───────────────┬─────────────────────────────────┘
                │ GitHub Contents API（机器人 PAT）
                ▼
        GitHub 仓库 main 分支
        ├─ src/content/*.json     内容数据（唯一事实源）
        └─ public/photos|qr|…     媒体文件
                │ git push 触发
                ▼
        Vercel 自动构建 → 约 3 分钟全网生效
```

**设计原则**

1. 零新增 npm 依赖（前后端都是），构建产物与现在同量级；
2. 成员视角只有"网址 + 账号密码 + 上传按钮"，GitHub 对成员不可见；
3. 内容文件 schema 是三方契约（前台读取层 ↔ JSON ↔ 后台表单），变更需同步三处；
4. 前台对内容层故障完全免疫（逐字段兜底，永不白屏）；
5. 迁移预留：服务端写入目标收敛在 `api/content.js` 一个文件内。

## 3. 内容层设计

### 3.1 JSON Schema（五文件字段一览）

| 文件 | 字段 | 对应前台 |
| --- | --- | --- |
| `brand.json` | `site{name,school,slogan,eyebrow,intro[],tags[]}`、`stats[{value,label}]`、`contact{wechat,email}`、`siteUrl`、`faqs[{q,a}]` | Hero / StatsStrip / Faq / SiteFooter / SEO |
| `hero.json` | `heroSlides[]`（第 1 张 = LCP 图）、`heroMusic\|null` | Hero / HeroCarousel |
| `gallery.json` | `aboutImage`、`seasons[{name,desc,photo}]`、`activityTypes[]`、`works[]`、`featuredVideo{video,poster,hint,spec}` | About / Activities / Works |
| `endorsements.json` | `endorsements[]`（video/photo 判别联合）、`awardImage` | Highlights |
| `qrs.json` | `qrs[{key,src,label,note,file}]`（key: wx/qq/mp/dy）、`douyinUrl\|null` | Join / DarkroomDevPaper |

`PhotoSpec`、`EndorsementItem`、`QrItem` 类型定义继续从 `src/config/site.ts` 导出，**全部消费组件零改动**。

### 3.2 读取层（site.ts 改造）

- `import` 五个 JSON（`resolveJsonModule` 已开），经手写校验器逐字段清洗后导出；
- 校验器规格：`str/strArr/strOrNull/ratio/enum/photoSpec` 等约 40 行工具函数；任何字段缺失、类型错、空数组 → 回退**内置默认值**（即当前线上内容快照，硬编码在读取层）；
- 兜底语义对齐 PRD EB-1：页面不白屏、不出 `undefined`；`heroSlides` 兜底必须保证非空（首屏依赖）；
- 不做运行时 fetch（构建时打包，微信端零额外请求；PRD §6 已论证）。

### 3.3 内容写入规则

- 后台保存 = 全文件覆盖写（读-改-写整个 JSON，非增量 patch），简单且幂等；
- 服务端保存前校验：`JSON.parse` 合法性 + 文件名白名单；内容与远端相同时返回 `unchanged`，不产生空提交；
- 所有提交 message 格式：`后台:更新{区块} (by {账号})` / `后台:上传 {路径} (by {账号})` / `后台:回滚{区块}到 {sha} (by {账号})`——发布历史页直接消费这个格式。

## 4. 服务端设计（Vercel Functions，Node 20+，零依赖）

### 4.1 环境变量清单（Vercel Settings 配置）

| 变量 | 格式/示例 | 说明 |
| --- | --- | --- |
| `ADMIN_ACCOUNTS` | `{"miaomiao":"密码","zhouhongxu":"密码"}` | 每人一个账号；改完自动生效（无需重新部署，函数每次冷启动读取） |
| `ADMIN_SECRET` | 随机 ≥32 字符串 | Cookie 签名密钥；泄露即后台失守，需轮换 |
| `GITHUB_TOKEN` | Fine-grained PAT | **仅本仓库、仅 Contents: Read and write**；过期时间设 1 年，日历提醒续期 |
| `GITHUB_REPO` | `AdgaiWalker/jiaowai-shuying-landing` | 可选，有默认值 |
| `GITHUB_BRANCH` | `main` | 可选，有默认值 |

### 4.2 POST /api/login

```
请求  { user, pass }
成功  200 { ok:true, user }  + Set-Cookie: jwsy_admin={payload}.{hmac};
      HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=604800
失败  401 { error:"账号或密码不对" }
锁定  429 { error:"尝试次数过多，请 10 分钟后再试" }
```

- 密码比对用 `crypto.timingSafeEqual` 防时序攻击；
- 会话 payload：`base64url({u,exp})` + HMAC-SHA256 签名，7 天有效；无状态、无存储；
- 限速：进程内存 Map，同 IP 连续失败 5 次 → 锁 10 分钟（Serverless 实例级精度，对 4~5 人规模足够，攻击者绕实例的成本远超收益）。

### 4.3 GET /api/content（需会话）

| 参数 | 返回 |
| --- | --- |
| `?what=content` | `{ ok, user, content:{brand,hero,gallery,endorsements,qrs} }` |
| `?what=history` | `{ ok, history:[{sha,author,message,date}] }`：五个内容文件各自 `commits?path=` 最近 15 条按 sha 去重合并、按时间倒序取前 20 |

### 4.4 POST /api/content（需会话）

| action | 参数 | 服务端行为 | 成功返回 |
| --- | --- | --- | --- |
| `save` | `file`（五文件白名单键）、`content`（JSON 字符串） | 校验合法 JSON → 与远端 diff → 相同则短路 → PUT Contents API | `{ok}` 或 `{ok,unchanged}` |
| `upload` | `path`、`content`（base64） | 路径白名单 `public/{photos,qr,videos,audio}/`，扩展名白名单 `jpg/jpeg/png/webp/mp4/m4a`，大小 0 < x ≤ 2MB → PUT | `{ok}` |
| `revert` | `sha`（7~40 位 hex） | 对五个内容文件分别读 `ref=sha` 版本，逐个 PUT 回 main（带原 sha 防冲突） | `{ok, changed:n}` |

统一错误：`400` 参数/内容非法（带中文原因）、`401` 未登录、`500` GitHub API 异常（透传前 300 字符，便于排查）。所有响应 `Cache-Control: no-store`。

### 4.5 GitHub API 封装（_lib.js）

- `gh(path, opts)`：统一 Accept / Bearer / API-Version 头，非 2xx 抛带 status 的错误；
- `getFileMeta / getFileBase64 / putFile / readJsonFile`：覆盖"读 meta 拿 sha → PUT 带 sha"的乐观锁流程（409 冲突时错误信息提示"刚有人保存过，请刷新重试"）。

## 5. 后台前端设计（public/admin/index.html）

### 5.1 技术形态

- 单文件、原生 JS（ES5 风格 IIFE）、无框架无构建；延续原型视觉（炭黑 + 摄影红 + 直角、140ms 回弹按压、`prefers-reduced-motion` 适配、safe-area 适配）；
- 移动端优先（管理组主场景为微信内置浏览器）；`<input type=file accept>` 直调相机/相册。

### 5.2 页面结构

```
登录视图 → 应用壳（顶栏：标识/账号/退出）
         ├─ 概览   换码预警卡（跳转二维码页）/ 四通道状态 / 最近发布 3 条 / 渠道入口
         ├─ 二维码 四通道卡片：预览图 + 上传按钮（即时提交）+ 说明文字（随「保存文案修改」批量提交）
         ├─ 橱窗   子分区：作品位（替换图/改 caption）/ 四季（名称/描述/图）/ 首屏轮播（替换/删除/新增，第 1 张标注 LCP ≤500KB）/ 文案（slogan/介绍/联系方式）
         └─ 历史   提交列表（作者/说明/时间/sha）+ 每行「回滚」（confirm 确认）
```

### 5.3 关键交互规则

- **登录态探测**：进入页面即 GET `?what=content`，200 直接进后台，401 停登录页——二次访问免登录（7 天）；
- **上传即时生效**：图片上传成功即提交仓库并刷新缩略图（URL 加 `?v=时间戳` 破缓存），不依赖表单保存；
- **保存提示统一话术**："已提交发布 · 约 3 分钟后上线"，保存后自动刷新历史列表（对齐 R-2 预期管理）；
- **失败可读**：所有 API 错误以 toast 展示服务端中文原因；401 自动踢回登录页；
- 全部动态内容 `esc()` 转义，杜绝存储型 XSS（内容进 JSON → 前台/后台渲染两端都安全）。

## 6. 安全设计清单

| 威胁 | 对策 |
| --- | --- |
| 登录爆破 | IP 限速（5 次/10 分钟）+ timingSafeEqual |
| 会话伪造/篡改 | HMAC-SHA256 签名，密钥仅存环境变量；HttpOnly + Secure + SameSite=Lax |
| Cookie 被带去恶意站（CSRF） | 写操作仅 POST + JSON Content-Type；SameSite=Lax 拦截跨站表单 |
| 越权写任意文件 | 路径前缀 + 扩展名 + 大小白名单，五 JSON 文件名白名单 |
| Token 泄露影响面 | Fine-grained PAT 仅 Contents 写权限，单仓库；可随时吊销 |
| XSS | 后台渲染全转义；前台经读取层类型清洗 |
| 仓库被塞大文件 | 服务端 2MB 硬限制（PRD EB-6；后续可加 GitHub Action 自动压缩，列为增强项） |
| 密码明文入 Git | 密码只存 Vercel 环境变量，仓库内无任何凭据 |

## 7. 发布、回滚与故障兜底（映射 PRD EB 表）

| 场景 | 机制 | 本方案落点 |
| --- | --- | --- |
| 正常发布 | 保存 → push → Vercel 构建 | ~3 分钟生效；构建失败时 Vercel 保留上次成功部署（EB-3） |
| 内容误改 | 历史页一键回滚 | `revert` action 把五文件恢复到指定提交 |
| 后台/接口故障 | 开发者 GitHub 网页/App 直改 JSON 或传图（EB-4） | schema 不变即可；写入《使用说明》 |
| JSON 被改坏 | 前台逐字段兜底（EB-1） | 读取层默认值快照 |
| Token 过期 | 上传/保存报 500 + 透传信息 | 部署手册写明续期步骤 |

## 9. 明确不做（本期内）

- 图片服务端压缩/转码（客户端约束 ≤2MB，超限提示压缩工具）；
- 富文本编辑、预览态、草稿箱（保存即发布，git 即草稿）；
- 多级权限/审批流（全员等权，靠账号署名 + 回滚兜错）;
- 运行时 fetch 内容（保持构建时打包）；
- NAS 直连/内网穿透（仅保留 `api/content.js` 写入目标的替换点）。
